# Alert assessment reliability — 19 October 2026

The former ingestion path committed a wide vital before calling `evaluate_new_vital`; a later evaluation failure could leave the reading without an alert. Migration `20261019_0019` adds `vital_assessments` with unique `vital_id`, state, attempt count, last error type and update time. Existing records are marked `legacy_unknown`; this does **not** retrospectively certify their assessments.

`backend/measurement_ingestion.py` now writes a `pending` assessment marker in the same transaction as a new vital. `backend/assessment_processing.py` claims the marker, calls deterministic/optional research assessment, records `completed` or durable `failed`, and can retry after a crash or exception. The background loop in `backend/main.py` reconciles up to 20 pending/failed/stale-processing rows each minute. Automatic attempts stop after five failures so poison records remain visible for investigation rather than retrying indefinitely. `GET /vitals/{patient_id}/assessment-states` exposes the state under normal patient access control. A failed assessment does not erase the accepted observation.

The minute monitor now performs its synchronous database and optional model work in a worker thread with a separate session, so reconciliation cannot block the ASGI event loop. A focused test verifies that offloading boundary. The same cycle marks device sync attempts still pending after 30 minutes as interrupted without rewriting a later success.

For sparse device groups, deterministic assessment uses only observed fields. Urgent cases use the existing case deduplication and clinician notification rules; notification **read** state remains separate from case acknowledgement/resolution. Updated case links open the clinical tab in the Care Workspace. The existing deterministic urgent rule does not require ML or Groq.

The fault-injection regression verifies that an injected assessment exception leaves a `failed` marker and that a later retry marks it `completed`; the sparse critical test verifies a review case with missing fields explicit. For an urgent case, the case and its assessment marker are committed together, reducing duplicate-critical-alert risk after a crash. Local migration and focused tests passed. **Remaining limits:** non-alert model prediction branches can still commit before the marker reaches `completed`, so exact-once prediction/audit semantics need multi-worker crash testing. Redis outage and end-to-end clinician acknowledgement also require controlled testing. No production alert path was exercised because the backend host is suspended.
