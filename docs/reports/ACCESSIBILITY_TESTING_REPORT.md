# Accessibility and mobile testing — 19 October 2026

The representative workspace browser suite checks doctor, nurse, patient, administrator, model, assistant, connected-device, research and monitoring routes with synthetic fixtures. It renders light and dark themes at 1440, 768 and 390 px, checks for horizontal page overflow, and retains representative desktop/mobile screenshots in `docs/evidence/`. The current full Playwright run passed **28 tests with one existing skip**. Frontend lint and production build also passed; exact commands and scope are in `REGRESSION_TESTING_REPORT.md`.

Automated axe checks found no serious or critical violations in the reviewed workspace states. Tests also cover the public login/register views, a 200% zoom reflow check, reduced-motion preference, the skip-to-content link, monitoring filter keyboard activation, and responsive navigation. The connected-device table has an explicit mobile sideways-scroll cue; sparse values and sync states use text in addition to colour. The doctor vital trend and research curves retain table or textual alternatives.

These checks are bounded: they do not constitute a WCAG conformance claim or prove every route, modal, validation state, screen reader, operating system or browser combination. The secondary medication, appointment, report, referral, documentation, settings and account-security routes still need a complete role/state matrix, keyboard task completion and manual assistive-technology review. Current screenshots are fixture-based presentation evidence, not proof of production API availability or clinical accuracy.
