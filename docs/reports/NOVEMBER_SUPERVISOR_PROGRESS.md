# November supervisor progress evidence — prepared 19 October 2026

Health Risk Dashboard 2.0 has moved beyond a visual prototype in this working tree. The new PhysioNet preparation and evaluation path uses observed next-window HR/BP labels, excludes unresolved target windows and invalid values, and keeps fitting, selection, calibration, threshold selection and testing patient-disjoint. The corrected candidate was evaluated on held-out Set A and untouched Set B. It **failed** the configured Set A sensitivity gate (0.585 against 0.60), is marked `approved_for_inference=false`, and has not replaced the installed legacy research artifact. The source is retrospective ICU data; it does not validate outpatient wearable predictions. See `ML_PIPELINE_VALIDATION_REPORT.md`.

Device ingestion now persists partial Withings groups with source IDs, missing fields and assessment state rather than requiring a complete vital bundle. Provider deliveries have a patient-scoped sync-attempt history, accepted/rejected counts and interrupted-attempt marking. Deterministic critical checks operate only on observed fields. Wide-vital assessment has a durable pending/failed/completed marker and reconciliation retries. The local development PostgreSQL migration to revision `20261019_0020` passed. See `WEARABLE_INGESTION_UPGRADE_REPORT.md` and `ALERT_RELIABILITY_REPORT.md`.

The frontend has distinct representative doctor, nurse, patient, administrator, model, assistant, device and monitoring workspaces with light/dark responsive evidence. The new device and model views make provenance and research limits explicit. Backend and browser regression results are in `REGRESSION_TESTING_REPORT.md`; screenshots and fixture limitations are in `docs/evidence/WORKSPACE_REVIEW.md`.

The most significant open operational issue is external: on 19 October the public frontend responded, but the hosted backend returned 503 “Service Suspended”. No production account or patient records were changed. Authenticated live smoke and provider reconciliation must wait for hosting restoration and an authorised synthetic test account. The remaining engineering priorities are multi-worker recovery evidence, complete route-state and accessibility coverage, real provider end-to-end verification, and research validity work before any claim of clinical utility. The current evidence does **not** establish the proposed 80% milestone or deployment readiness; that judgement needs an agreed rubric and completed live checks.
