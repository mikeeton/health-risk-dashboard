## Production read-only check

The local backend intermittently stopped responding to smoke requests after the development migration. The minute reconciliation loop had run blocking database/model work on the ASGI event loop; it now runs that work in a separate thread with its own database session. The retry identified a second path: live notification and vital sockets could wait for a database connection on the ASGI event loop when the small pool was busy. Those database checks now run in worker threads, and liveness no longer needs a thread-pool slot. After restart, the full browser suite passed while 25/25 liveness and 10/10 readiness probes returned HTTP 200; the slowest readiness probe took 267 ms and the new log showed no pool timeout. This bounded local run does not prove sustained uptime; the hosted availability finding below is separate.

On **19 October 2026**, a read-only HTTP request returned **200** for `https://aihealthcaredashboard.vercel.app/` and **503** for `https://health-risk-dashboard-api.onrender.com/health/ready`.
