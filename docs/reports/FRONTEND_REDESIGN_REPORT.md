# Frontend redesign and section review — 19 October 2026

The current frontend uses one light clinical design system with a matching dark theme, shared navigation and role-aware routes. Section layouts follow their tasks: doctor clinical review, nurse worklists, patient measurement explanations, administrator operations, model research evidence, AI evidence review, device connections and alert monitoring. `FRONTEND_DESIGN_SYSTEM.md` records the tokens and component rules. This is a working-tree implementation, not a deployed release.

This development batch added the dedicated `DevicesHub` route with connection state, recent device readings, sparse observations and a persistent provider-attempt timeline. Partial measurements show units, timestamp, source, assessment state and absent fields. The model intelligence panel separates installed legacy inference from the observed HR/BP candidate, shows saved ROC and precision–recall curves, confidence intervals and false-prompt burden, and states that the candidate is not serving predictions. The care workspace preserves query context when switching tabs, so alert links open the intended clinical register. Monitoring distinguishes notification read state from case acknowledgement. AI assistant and authentication surfaces were also refined in the current working tree.

The restricted administrator research page now counts genuine SHAP and excluded fallback records separately. Its negative-outcome form lists only expired prediction windows, requests a source-based rationale, and explains that an observed-field proxy negative is not proof of event absence between measurements. The server independently checks the window and follow-up evidence.

Browser evidence is in `docs/evidence/WORKSPACE_REVIEW.md`. The baseline screenshots predate the redesign; current captures use synthetic Playwright fixtures, so they show visual progression rather than matched-data comparison. The review checks light and dark themes at 1440, 768 and 390 px across representative sections, with no horizontal overflow in those states. Automated axe checks found no serious or critical violations in the reviewed sections. Keyboard checks cover the skip link and monitoring filter. These checks do not certify every page, interaction, browser or assistive technology.

Remaining design work is a route-by-route audit of the older medication, appointments, reports, referrals, settings, documentation and account-security screens, including their loading, empty, validation and error states. Real provider and production data were not used for screenshots. No chart is inferred from missing clinical measurements.

The Operations page no longer names Render in the overdue-monitoring description. A focused synthetic browser check passed at light/dark desktop and mobile widths with no horizontal overflow or serious/critical Axe findings; final screenshots are in `docs/evidence/secondary-theme-2026-10-21/`. The remaining route-level audit still includes other specialist pages and manual assistive-technology review.
