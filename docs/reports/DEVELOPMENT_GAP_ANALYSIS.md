# Prioritised development gap analysis

Date: 19 October 2026. Baseline sources: repository files, [previous audit](SUPERVISOR_MEETING_PREPARATION.md), retained evaluation/deployment evidence and current working tree. P0 means invalid scientific assumption or serious safety/security risk; P1 core reliability/usability; P2 maintainability; P3 future study. Severity describes a research prototype, not a clinical safety rating.

| Priority / issue | Evidence and affected files | Impact and confirmed root cause | Solution, dependency and verification | Dissertation relevance |
|---|---|---|---|---|
| **P0: future-event label can come from stale value** | `backend/scripts/prepare_physionet_2012.py` used `ffill()` before future-bin comparison. | The model can appear to predict a fresh event when the value was carried forward. | Preserve legacy mode; generate observed-next-window labels from unfilled next bin; audit exclusions and retrain to a new version. Depends on raw data and scientific framing. Unit-test empty follow-up and stale critical readings; compare cohorts and metrics. | Correct outcome definition and every performance claim. |
| **P0: oxygen variable mismatch** | Script expects `SpO2`; prepared Set A/B `spo2` are wholly missing. PhysioNet lists `SaO2`. | Current model has no oxygen input. SaO2 cannot silently be relabelled wearable SpO2. | Inspect raw parameter frequency; retain SaO2 separately if used, with clinical rationale and new feature/version. Verify missingness and provenance before retraining. | Explicitly qualify oxygen claims. |
| **P1: low model precision** | `backend/artifacts/ml/evaluation.json`: internal 55 TP/1,403 FP; Set B 373 TP/7,551 FP at 0.014. | Potential alert overload; threshold optimises sensitivity/specificity rather than workload. | Correct labels first, then prespecify workload and threshold analysis on validation only. Verify untouched test and Set B metrics. | Report base rate, PR-AUC, precision and absolute burden. |
| **P1: sparse Withings groups skipped** | `backend/routes/integrations_withings.py` maps four vital fields but requires eight `WIDE_VITAL_FIELDS`. | Valid independent measurements are discarded; wide schema and score function assume unrelated fields. | Design partial-observation storage and risk behaviour; migration if schema changes. Verify fixtures for HR, BP, saturation, duplicates and missingness. | Integration is prototype-only until end-to-end evidence. |
| **P1: post-commit alert gap** | `backend/measurement_ingestion.py` commits before `evaluate_new_vital`. | Failure can leave a measurement stored without assessed alert. | Durable assessment state/outbox plus idempotent retry, migration and injected-failure test. | State reliability limit and recovery evidence. |
| **P1: deployment evidence incomplete** | `docs/dissertation-evidence/deployment/production-smoke-2026-09-14.json`: frontend reachable, backend readiness 503; auth checks skipped. | Configured deployment does not prove live end-to-end availability. | Run fresh authenticated smoke only against an authorised environment. | Separate configuration from observed operation. |
| **P1: inconsistent theme and presentation** | Theme originally initialised in authenticated toggle; `frontend/src/styles/index.css` has role-independent but mixed hard-coded surface styles and motion. | Public pages can start in wrong theme; interface lacks consistent visual hierarchy. | App-start theme fix and shared semantic tokens/shell, followed by page audits. Build, browser theme test and screenshots at mobile/desktop widths. | Clearer November demonstration. |
| **P1: explanation method can be misnamed** | `backend/ml_engine/registry.py` has coefficient fallback; retained ten-request sample used fallback. | Users may mistake coefficients for SHAP or causal evidence. | Expose actual method and model metadata; verify fallback UI and API. | Accurate explainability claim. |
| **P2: dated test/dependency claims** | Dissertation August counts and July zero-vulnerability note differ from later runs; last local install reported three npm advisories. | Reproducibility and security posture are difficult to assess. | Snapshot commands, environment, commit, audit results and artifact hashes. | Align thesis claims to dated evidence. |
| **P2: repeated UI patterns** | `frontend/src/app/pages` and `components` mix raw utility classes and shared primitives. | Form, card and table details drift across roles. | Incrementally apply design tokens and accessible shared components, checking every role. | Maintainability and visual cohesion. |
| **P3: clinical validation** | `backend/routes/research.py` provides capture routes but no completed prospective/outpatient study. | Clinical effectiveness cannot be inferred. | Governed representative cohort, clinician review, shadow trial, usability and ethics approval. | Future work, outside prototype milestone. |

This is a ranked working register. A row is complete only when its verification and documentation have been performed; code presence alone is insufficient.
