# Production smoke evidence

The dated JSON report is generated by the non-sensitive smoke checker:

```powershell
backend\venv\Scripts\python.exe scripts\production_smoke.py `
  --api-url https://YOUR_SERVICE.onrender.com `
  --frontend-url https://YOUR_PROJECT.vercel.app `
  --output docs\dissertation-evidence\deployment\production-smoke-YYYY-MM-DD.json
```

Public frontend, liveness, and readiness checks always run. To exercise login
and the authenticated read-only workflow, set `SMOKE_EMAIL`, `SMOKE_PASSWORD`,
and, when required, `SMOKE_MFA_CODE` in the process environment. The checker
keeps tokens in memory, attempts logout, and records only status/metadata—never
credentials, tokens, response bodies, or patient details.

The 14 September 2026 run found the Vercel frontend available with the expected
security headers. Both Render health routes returned HTTP 503 and the routing
header classified the service as suspended. The authenticated workflow was
therefore skipped rather than reported as passed. Resume or replace the Render
service, migrate Neon to the current head, configure the final origins, and run
the checker again before claiming successful deployment.
